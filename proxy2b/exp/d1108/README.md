# d1108 · Self-calibration on the user's agent sessions (0.8B, 4070)

Question (user, 2026-11-04): do continuations the model generates itself, in real agentic contexts, make better
quantizer statistics (Σdy² H_out, input Hessians) or healing data than calib (qad) or the raw sessions? If so, at what
blend weight with calib? Decided globally (adopt / blend / drop), not as knapsack options.

Data (`sgprep.py`, `sggen.py`, `sgbuild.py`): the user's sessions (pisess v2, private; 4070 = our machine), split by
session 4:1 train / eval. Prompts = system block + the latest context, exactly 3,072 tokens, ending at an assistant
turn; the 0.8B bf16 generates its own turn (generation_config sampling, ≤ 768 tokens; filtered: < 32 tokens or a
16-gram repeated > 6 times). Train docs = the last 2,048 tokens of prompt + continuation, scored on the generated
tokens only. Raw arm = 2,048-token windows of the train sessions scored on the other model's assistant turns.
Agentic eval golden `g-agent` = eval-session prompts + continuations, whole, bf16 0.8B, scored on generated tokens.

Arms. Every quant: our tuned settings, K3 and K2, seeds 0 and 1, scored on calib search (`/data/g08-search1`) and
`g-agent`, paired.
- **H_out (Σdy², gen-masked, 1,024 windows, as c23):** base `dygm` (calib qad = w 0); self-generated `C` blended into
  c23 at w 0.25 / 0.5 / 1; raw `B` at w 0.5 / 1 (`blend.py hout`).
- **Input Hessians:** calib H_in (published-style, all calib) vs blended with self-generated text's at w 0.5 / 1
  (`blend.py hin`), H_out = c23 in all three.
- **Healing (scale-only, one pass, 2,048 windows, as d1105 `sp`):** on the edy → swj → asym stack, data qad (`sp`,
  existing) vs raw `B` vs self-generated `C`.
- **Arm T (added 2026-11-04 ~6:40 PM CST, before data):** turboderp's SC calibration trace for this model
  (`cal_trace.json`, Qwen3.8-27B 6.00 bpw sampling ~140 seeded conversations, thinking on, 217 rows, 509k generated
  tokens; public, HF `turboderp/Qwen3.8-27B-exl3`): last 2,048 tokens a row, scored on the response. Same H_out
  weights (0.5, 1; windows reused with fresh labels: 217 rows < 1,024) and a healing arm. Reported, no rule of its own
  (off-policy for the 0.8B, like D); it says whether general 27B-generated text helps the statistics.
- Arm D (the 27B's continuations of the same boundaries) waits for iceman time.

Pass rules (written 2026-11-04 ~6:00 PM CST, before data). Ratios = mean over the 2 seeds of the paired KL ratio vs
the arm's base, at K3 and K2:
- **Self-generated statistics are adopted at weight w\*** = the w with the lowest mean log ratio over both goldens
  (equal weight), if at w\* the `g-agent` ratio is ≤ 0.98 at both K **and** the calib ratio ≤ 1.01 at both K (no
  real calib regression). Otherwise calib stays. Same rule separately for H_out and H_in.
- **Self-generated healing data** is adopted (as a share; the share is a 27B-side choice) if `C` vs `sp` is ≤ 0.98 on
  `g-agent` and ≤ 1.01 on calib at both K.
- **On-policy check:** `C` vs `B` at equal weight reported for the record (does self-generation beat the raw
  sessions?), no rule.
- Caveats: the 0.8B is a weak agent (its turns are often poor); the eval golden is self-generated by the same model
  (favours C by construction on that golden: the calib golden guards against it). Runtime cost: none.
