# RULES-17803 — GDN a/b at high bpw: T4 vs T5 / T6 vs bf16 on the 5.0 / 6.0 / 6.5 incumbents (w149, #178-03)

Written and committed alone before any arm is scored (11-13 5:35 PM CST). Pre-registration is attested by this file's
git commit.

**Question.** #178 (w142, RULES-178) tested quantized a/b only at 2.5 and 4.0; T4 was then adopted at every size
(lead 11-13 1:20 PM CST; served by w147, #178-02, 0.00918 bpw saved incl. scale vectors). At 5–6.5 bpw the trunk sits at
K5–K7, so K4 a/b is the coarsest tensor while the bytes it frees buy less (the driver's slope falls from 1.145 at 4.0 to
0.158 at 6.5). Does T4 still pay for itself there, and if not, which arm does?

**Arms (a/b only; everything else identical within a size).**
| arm | form | bpw saved (incl. scales) |
|---|---|---|
| B | bf16 a/b (today's container form) | 0 |
| T4 / T5 / T6 | our trellis (codebook i8 = mul1i8), K4 / K5 / K6, a\|b fused and padded to 128 rows (w142's donors, `/data/q27/w142/tq/ab-T{4,5,6}.safetensors` on ds8; T4 = w147's served donor) | 0.00918 / 0.00801 / 0.00684 |

bpw saved = (16 − K·128/96) × 23,592,960 / 26,895,998,464 − 0.000176 (the per-layer scale vectors: w147's packed T4 is
0.00918, against 0.009356 for the codes alone; the same vectors at every K). Denominator = the driver's (container)
metric, the one its slopes are measured in.

All T arms are **simulated**, as in #178: the decoded a/b values are written as bf16 over the container's a/b planes
(w142's `abpatch.py`); w147 showed served ≈ simulated (−4.3e-4 KLD, within noise).

**Statistic (as RULES-178).** Per document, the KL sum over the golden's positions (`rxrun.hostd.doc_sums`).
- d = mean over p ∈ {c, x} of log(Σ_p KL_arm / Σ_p KL_B) (#171's pmean); also per part.
- 95% CI from 2,000 bootstrap resamples of documents, stratified by part, paired.
- Trunk price of the freed bytes: g = b_s × bpw saved, b_s = the driver's last slope (`drv/frontier.json`,
  RULES-value): **5.0 → 0.781, 6.0 → 0.350, 6.5 → 0.158**. So g(T4 / T5 / T6) = 5.0: 0.717 / 0.626 / 0.534 %;
  6.0: 0.321 / 0.280 / 0.239 %; 6.5: 0.145 / 0.127 / 0.108 %. Net N = d − g (negative = the arm pays for itself).

**Reading (fixed now).**
- Per arm and size, RULES-178's reading: **adopted** if N < 0 and d's 95% CI upper end < g + 0.005; **rejected** if
  d's CI lower end > g; otherwise **null**. Reported for all nine (size, arm) pairs.
- **Per-size choice (the decision):** T4 stays at a size if its KL change is below the price of its bytes (N_T4 < 0,
  point estimate). Otherwise the cheapest arm that is, in order T5, then T6 (first with N < 0). If none, bf16 a/b.
- A choice that moves a size away from T4 while T4's reading is **null** (its CI still covers g) is reported as
  "noise-level". It is still the rule's pick, but the lead should know that a second slice could flip it.
- Confounder check (AGENTS.md): if any arm shows |d| > 3% (several times #178's largest), it is "unverified" until the
  census identity above holds (it does by construction) and it repeats on a second slice. No second slice is scored
  inside this rule.
- Also reported, not used for the choice: KLD per arm, per-part d, both size metrics' bpw saved (container
  denominator above; trunk + head denominator in the result table).
