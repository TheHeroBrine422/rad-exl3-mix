# #100c · hash codebook, small real run: 0.8B KL (4070) and decode speed (gfx1201) — w48, 2026-11-06

User 11-06: "try the fixed code hash just to see the performance / quality difference on a small scale run". #100
(`r100.md`, w27 CPU proxy) left the hash codebook (IQR-V4's `(umul24(s, A) + B) & 0x3F3F3F3F`, byte sum − 126) with
NO AUTOMATIC CALL; w29 (`docs/design/kernel-opts.md` "#100 results") measured the mul1i8 closed form but not the hash
(card busy). This run measures both on a small scale. w46 re-runs the CPU proxy on settle.py (not duplicated here).
Code: `v3/e3/exl3hash/` (quantizer codebook), `r100c/` (drivers, report, bench hook, patch).
**Runtime cost:** the hash would change **decode and prefill** (the codebook decode ALU in the GEMV and in the A8
wdec8 pass) and the format (every level requantized). Quality arms are fake-quant: no kernel runs them.

## Rules (written 2026-11-06 ~12:35 PM CST, before any data)

**Quality arms (0.8B, 4070).** d1112's trunk quant "edy" (`proxy2b/q2b.sh 08 K CB`: qtf2, scaled Hessian, σ 0.025,
σ_in 0.005, Σdy² H_out c18 `hdiag-snap1024-dy`, σ_out 0.01), every trunk linear, no swj / writers / healing, at
K2 / K3 / K4, seed offsets 0 and 1, two codebooks:
- `i8` = mul1i8 (`--codebook i8`, the V3 default, stock ourq.py),
- `hash` = hash codebook with **A = 0xd0474b** (w27's searched global A; r100.md: "if adopted, use a searched A"),
  B = 0x2545F491 (IQR's), on the same int8 grid as mul1i8 (value = q · 4 k_inv, q = byte sum − 126; both sd ≈ 36.9
  int8 steps), patched ourq.py `--codebook hash`.
- readout only, if GPU time allows: `hiqr` = IQR's own A = 0xB5297B, seed 0, K2 / K3 / K4.

Scoring is **fake-quant** (the runtime has no hash decoder): `--save-wq` dequantized weights substituted into the
bf16 model, `evalq.py` (bf16 KV, gen-masked mean KL), as every 0.8B proxy run. Goldens: **search** `g08-search1`
(deciding), **verify** `g08-verify1` (check only). Pairs per (K, seed): `pcmp.py` ratio hash / i8 (per-document
bootstrap); per K the geometric mean over the 2 seeds ("geo").

**Speed (gfx1201 card 0, q2 insert hook).** w29's five exl3i builds of one source tree (`/data/tp/w29/b-*`: `old` =
mul1i8 today, `cf` = mul1i8 closed form (the default since 716b811), `iqrh` = IQR's hash in mul1i8's slot, speed
only, `abl` = no decode ALU, `cfz`), `bench_twopass` at K2–5: M 2048 A8 path + phases (wdec8 = the decode-to-int8
pass), M 1 / 4 / 16 f16 GEMV (nt_pass, the decode path). Layer = 48 GDN : 16 attention. Valid only if the card
samples idle (GFX ≤ 5%) before and after a pass, and K4 `cf` GEMV attn_k at M 1 is 50–75 µs (w29's clean ≈ 60).
Values/s = N·K / t of the per-shape wdec8 (and GEMV M 1) times.

**Verdict (the task's bar), per piece:**
- **Quality passes** if the search geo hash / i8 ≤ **1.010 at each of K2, K3, K4**. **Fails** if > 1.010 at any of
  them. If search passes but verify geo > 1.020 at some K, the pass is labelled **fragile** (not a pass).
  (Noise: one 0.8B pair has paired SE ≈ 0.4–0.6%; two seeds ≈ 0.3–0.45% on the geo. A K within ±0.5% of 1.010 is
  reported as "at the bar"; the call is still made on the point estimate as written.)
- **Speed passes** if the hash GEMV layer time at **M 1** is ≥ 15% faster than the **closed form** (`cf`):
  t_cf / t_iqrh ≥ 1.15 at each of K2, K3, K4 (median over passes). Reported, not deciding: M 4 / 16, wdec8, A8
  layer time (prefill), the decode share vs `abl`, and the same against `old`.
- **Hash adopted (bar met)** only if both pass. Otherwise the bar is not met; per the #100 amendment the final
  decision stays the user's from the trade-off table (quality cost as equal-quality bpw at each K next to measured
  decode and prefill speedups); > ×1.05 at any K in 2–4 is a reject regardless.
- Side checks (reported): the `i8` arms reproduce d1112's `k{K}ste(_s1)` search scores (same recipe and code; expect
  identical KL, else say how far); `hiqr` vs `hash` (does the searched A transfer from the proxy to real KL?);
  proxy-error ratio per tensor class from `proxy.jsonl` (compare with w27's CPU table).

## Results

### Quality (4070, 2026-11-06 12:53–2:42 PM CST)

`stamp-*.json`, `check.log`); per-position score files on the 4070 in `/data/yb/w48/r100c/*.f32`. Self-test first

kernel paths (qtf2 at K2 / 3 / 4 / 2.5, exl3cb at K5); MSE on N(0,1) K2 0.0693, K3 0.0179, K4 0.0048.

**Quality verdict: FAIL** — search geo above 1.010 at every K (×1.026 / ×1.040 / ×1.016 at K2 / K3 / K4), all
below ×1.05, so no hard reject under the #100 amendment. Verify agrees at K2 and K3 (×1.025 / ×1.029). At K4,
verify is flat (×1.000), so the K4 cost is uncertain (≈ 0–1.6%); K2–3 is not.

Side checks:
- **Reproduction:** the i8 arms equal d1112's `k{K}ste(_s1)` search scores to 1.00000 at every K and seed (same
  recipe, deterministic quantizer): the control is d1112's trunk quant exactly.
- **IQR's own A** (`hiqr` 0xB5297B, seed 0) vs i8, search / verify: K2 1.025 / 1.025, K3 1.038 / 1.016, K4 1.028 /
  1.029; vs the searched A, search: K2 1.009, K3 1.001, K4 1.005. The searched A is a little better (as w27's
  iid search said), but the gap to mul1i8 is mostly the code family, not A.
- **Proxy error vs KL:** exllamav3's per-tensor proxy error (H_out-weighted, after the scale refit) is only
  +0.8–0.9% for the hash (geo over 300 tensors; 0.7–1.3% for every tensor class, every K), in line with w27's CPU
  proxy (+1.2–1.4% at K2–3.5 on 27B tensors). The model KL cost is **3–4× that** (+2.6% / +4.0% at K2 / K3).
  Earlier codebook changes ran 1:1 to 1.5–2× proxy → KL (kernel-opts.md). So the per-tensor proxy *underprices*
  this codebook. Unexplained. One guess: the hash's 2^K successors of a state differ by j·A, a structured
  value set, which could make errors correlate across a tile or a row in a way a per-tensor trace metric with
  a diagonal H_out doesn't see. A per-layer swap (hash in one layer group at a time) would locate it, if it
  matters.
- Same decode, A only changes a constant; the shards carry exllamav3's mul1 marker (no runtime reads hash codes).

the no-decode floor.

## Verdict and trade-off

**Bar not met: the hash is not adopted.** Quality fails (×1.016–1.040 > 1.010 at every K) and speed fails at K4.
Neither piece reaches the ×1.05 hard reject, so per the #100 amendment the user still decides from this table:

| K | KL cost (0.8B search geo) | equal-quality bpw | decode M 1 vs closed form | decode M 16 | prefill (A8 layer) |
|---|---|---|---|---|---|
| 2 | +2.6% (verify +2.5%) | +0.015 | −14% time (×1.156) | −10% | ±0 |
| 3 | +4.0% (verify +2.9%) | +0.025 | −15% (×1.176) | −11% | ±0 |
| 4 | +1.6% (verify +0.0%) | +0.011 | −11% (×1.126) | −8% | ±0 |

Reading (not the decision): the scored metric (KL, prefill) only loses. The gain is decode-only, which is not scored.
Mul1i8's closed form (already in, no requant) already took ~40% of today's → hash gap at M 1 (old → cf −7–9% of
the −18–22%).
The proxy underpriced the hash's KL cost by 3–4× (Quality, side checks), so w27's "≈ +0.01 bpw" was optimistic.
Recommendation: keep mul1i8 for V3. A hash-friendly codebook would need a design whose real-model KL matches
mul1i8's before it is worth the ladder requant.

## For the lead (merge / record)

- `v3/e3/exl3hash/` (new): the hash codebook for exllamav3's quantizer, with no fork or shared-loader edit. It
  generates a copy of the fork's `exllamav3_ext` with three `#ifdef EXL3_CB_HASH` hooks in `codebook.cuh` and builds
  it through exl3cb (`i8` variant) and exl3frac2 (`mul1` variant) via their `EXL3CB_DEFS` / `QTF2_DEFS` hooks, into
  `TORCH_EXTENSIONS_DIR/exl3hash-A-B`. Self-test: `hashcheck.py SRC`.
- `r100c/ourq-hash.patch` (+ why): `ourq.py --codebook hash` (A / B: env `EXL3HASH_A` / `_B`, default 0xd0474b /
  0x2545F491; requires `--frac-ext`). Its lines are tagged `# +cb` and the one changed line keeps a `#cb-was:`
  original, and `_io_canon` (a `+io` line) drops / restores them like `+io`. So **the stamps of mul1 / i8 / i4 / i8c
  runs are unchanged** (`r100c/stampcheck.py ORIG PATCHED` → identical canon), and a hash run's stamp carries
  `codebook: hash`, `hash_ab` and the exl3hash files. If the hash is dropped for good, the patch is optional (the
  experiment ran from a mirror: `r100c/setup4070.sh`).
