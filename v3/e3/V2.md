# V2.md — the shared trellis search core (viterbi2)

**You do not write a Viterbi search.** The search core is fixed: `viterbi2.c` implements the
EXL3/QTIP/CPTC bitshift trellis (Mao & Gray) for 16×16 tiles, with two backends and a
format-agnostic interface. Your job is the CODEBOOK (a state→value map) or a bounded value
snippet. Everything below is what you get and what you must do.

## The interface

```c
void viterbi2_tiles    (const float* x, float* out, int ntiles, const float* cb, int K, int V);
void viterbi2_tiles_tb (const float* x, float* out, int ntiles, const float* cb, int K, int V, int ntry);
```
- `x`/`out`: [ntiles][256] float32 (targets / quantized values)
- `cb`: **65536 × V float32 values — the codebook.** State s (16 bits) shifts K bits in per step,
  `s' = ((s << K) | j) & 0xffff`, and a step emits V values: value v of state s is `cb[s*V + v]`.
- `K`: bits per step (1..8); `V`: values per step (1 or 2); `ntry`: tail-biting roll candidates (1..16).
- `viterbi2_tiles` = free initial state; `viterbi2_tiles_tb` = tail-biting (start state = end state,
  QTIP Algorithm 4: ntry rolled free runs → constrained run with the wrap group).

Backends (bit-identical outputs, same interface):
- `libviterbi2.so` — scalar reference (readable, for debugging your map)
- `libviterbi2_avx2.so` — vectorized (default for scoring)

## What a "codebook" is (the whole family, one LUT)

| family | V | how cb is built | decode cost (ops/value, table) |
|---|---|---|---|
| E3 mul1 / mul1_i8 / gauss_i8 / int4grid | 1 | fitted table (ourq) | 1 LUT gather, 64 KB |
| **CPTC** (the paper) | 1 | decode map: `i = (a0·s mod 2^16)≫(16−6) + (a1·s mod 2^16)≫(…)` → 64-value table (or its −mirror), any grid | 2 int muls + add + 64 B gather |
| mad (our V3 hash) | 1 | byte-sum of exl3hash(s) → value | 1–3 ALU, 0 B |
| QTIP 1MAD | 1 | LCG(a=34038481,b=76625530) → sum 4 bytes → scale — precompute the LUT, or the VAL-macro template for zero-LUT decode | ≤4 ALU, 0 B |
| QTIP 3INST | 1 | LCG + fp16-magic XOR — same two options | 3 ALU, 0 B |
| QTIP HYB | **2** | hash x·x+x → 2D k-means LUT pair + sign flip → interleaved `cb[2s+v]` | ~2 ALU, small 2D LUT |
| QTIP RPTC | 1 | random-permutation LUT — **dropped from our sweep** (≈1MAD quality at 2 bits, 128 KB random gather = worst decode cost) | — |
| QuIP# E8 / lattice VQ | — | not a trellis — Python level, outside this interface | — |

**Building the CPTC LUT** (Python, from `cptc.py`): `decode_table(a0, a1, T)` already returns the
65536-entry state→value map — feed it straight to the core.

## Custom value functions (bounded surface)

If your format is NOT a pure state→value map (e.g. the value depends on the target xi, on position,
or uses a metric other than squared error), you may supply a custom core:

1. Copy `viterbi2.c` → `viterbi2_<name>.c` (in your candidate dir).
2. Change ONLY the value expression in `ncost_pass` (and the matching `cb[...]` emit in
   `v2_run`/the final loops) — mark it with `/* CUSTOM VALUE: begin/end */`.
3. Rebuild both backends with the same flags as above.
4. **Self-test is mandatory before the judge sees it** (the Prop-1 template from the CPTC paper):
   your value function must reproduce the known scalar embedding at L=K
   (e.g. reduce to nearest-neighbor rounding, or to the cb[s] LUT when your parameters degenerate),
   0 mismatches on 16384 random tiles. A candidate failing its self-test is rejected.

## Rules

- The search DP (gmin/ncost/backtrace/tail-biting) is **frozen**: do not rewrite it. If you think
  the DP itself is the idea (new topology, different objective), say so in your report — the lead
  ports it; the fleet scores value maps, not searches.
- Bit-exactness: any new value map must give reproducible outputs (the two backends are
  bit-identical by construction — a map that breaks that has nondeterministic or backend-dependent
  arithmetic).
- Speed is the same for every candidate: you are judged on the value map, not on kernel tricks.
  (Kernel productionization of winners is Layer 1 — qtf2 — and not your job.)
