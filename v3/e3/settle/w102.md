## #136-01 · D-3: tail-biting search width (NTRY) and chained rings at the sub-1 levels (CPU)

**Question.** EXL3 codes a 16×16 tile as a 256-step tail-biting ring; exllamav3 / qtf2 find the wrap with one guess
(NTRY 1: a free run rolled by L/2, then a constrained run). #57 / #102 measured NTRY 16 and #102's chained rings (one
ring per n row tiles) at K2–4 only: −0.1 … −0.4%, not adopted. At sub-1 a tile carries only 32 (K0.125) / 128 (K0.5)
bits, so the 16-bit wrap window is a large share of the code, and both may matter more.

**Proxy.** w87's two-sided held-out proxy (`w87.md`; P2 transforms of one aligned 128-row block, exllamav3's scale
search with ourq's drift, H_A for the quantizer, held-out H_B1 / H_B2, bn1920 H_out with σ_out 0.01, per-output-channel
refit), i8 (`mul1x_i8`, #126), today's σ (K0.125 0.2; K0.5 inputs 0.05 / rest 0.025; K1 inputs 0.005 / rest 0.025),
natural (rev) LDLQ order. Tensors: w87's 27 (9 families × 3 layers), **sample 0**. K ∈ {0.125, 0.5, 1}.
The tile search is `w102/ring102.c`: #102's chained tail-biting search generalised to qtf2's sub-1 steps (0-bit
steps keep the state and read cb[s ^ salt(i)]; the trellis pattern is qtf2's mask, e.g. K0.125 = 1 bit at positions
7 and 15 of every 16).

Arms (`w102/job102.py d3`), all on the same rows, scale, metric:
- two-sided LDLQ (the production objective): **F** free start (the proxy's usual search; = w95's i8 rows), **T1**
  tail-biting NTRY 1 (production search), **T16** tail-biting NTRY 16 (rolls L/2, L/4, 3L/4, … as #57);
- one-sided block LDLQ (all 8 row tiles of a 16-column block searched together, so chains exist; #102's setup):
  **O0** free, **O1** tail-biting NTRY 1, **O4** chained, one ring per 4 consecutive row tiles (NTRY 1).
  Chains need the row tiles of a column block searched jointly, which the two-sided tile-by-tile LDLQ does not allow;
  the chain question (is one ring of 1,024 positions a better code than 4 rings of 256) is a format question that the
  one-sided pair answers paired.

**Gates.**
- **G1 (code, done before the rule):** `gate102.py` on colo: ring102.c's free search equals viterbi.c's
  `viterbi_tiles_pat` bit for bit at K0.125 / 0.25 / 0.5 / 1 / 1.5 / 2; its n = 1 tail-biting search equals
  `viterbi_tiles_tb` at K1 / K2, NTRY 1 and 16; its n = 4 chain equals #102's `viterbi_chain_tb` at K2; every sub-1
  output is a valid ring (0 shift / wrap violations) and decodes from its states. **PASS** (`data/w102/g1.json`).
- **G0 (before any ratio is read):** arm F's rel_B equals w95's stored i8 row (same tensor, sample 0, K, σ) within
  1e-6 relative on every (tensor, K). Fail → no ratio is read; diagnose.

**Statistics.** rel_B = two-sided held-out error (B = B1 + B2), per (tensor, K). Per K, geo mean over the tensors:
R_ntry(K) = rel_B(T16) / rel_B(T1); R_chain(K) = rel_B(O4) / rel_B(O1).

**Pass (from the task).**
- **NTRY:** at each K, **R_ntry(K) ≤ 0.995** (NTRY 16 ≥ 0.5% better) → propose NTRY 16 for that level's tile search
  (encoder only: format, decoders, bpw unchanged). The quant-time cost is reported (measured CPU search time ratio;
  the GPU search's two passes become 32; the level's share of time spent in the tile search, from logs where they
  exist). Otherwise NTRY 1 stays.
- **Chained:** at each K, **R_chain(K) ≤ 0.95** → a format / decoder note for the lead (#102's "Format and kernels"
  section applies); otherwise not adopted.
- Reported, not deciding: per family and group, a tensor-bootstrap 95% CI of each R, B1 / B2 / in-sample A, the
  one-sided rel; **T1 / F** (what the free-start proxy used by #90 / #126 / w87 / w100 misses at sub-1: the
  tail-biting cost) and O1 / O0; O4 / T16 (chains vs more wrap tries); CPU seconds per arm; the i.i.d. Gaussian table

- If Thor drops out: the rule is read on the tensors that finished, at least the 24 non-ffn_down ones (colo can run

## #136-02 · B-8: su / sv stored as 8-bit log instead of fp16 (CPU)

**Question.** The two per-channel scale vectors (input su, Kd entries; output sv, N entries) are fp16: 16 (N + Kd) /
(N Kd) bpw per tensor, ~0.006 bpw at 5120 × 5120. 8 bits each would save half. Does rounding them to an 8-bit log
format after the refit cost proxy error?

**Proxy.** As #136-01, two-sided LDLQ with the proxy's usual (free-start) search, i8, today's σ, K ∈ {0.5, 2.5, 4}, the
27 tensors × sample 0. One quantization per (tensor, K); the arms differ only in the stored scales (codes fixed).
Stored scales: su (the whole tensor's input scales incl. signs) and sv_final = sign × row RMS × the refit factor c of
each output channel (what refit_scales leaves in svh, up to a global constant).
Formats (`job102.py b8`):
- **fp16** (today), the reference;
- **L8** (the primary arm): 1 sign bit + 7-bit index on a uniform log2 grid from the vector's min to max |s| (two fp32
  numbers per vector, negligible); su's range is the tensor's own; sv's range is [min_N r · min c, max_N r · max c] (r
  over all N rows of the tensor, c of the proxy block, as the proxy has c for 128 rows only);
- reported only: L8su / L8sv (one side), L9 (sign + 8-bit log2), E4M3 (fp8 × one fp32 scale per vector), L8r (su to
  L8 first, the output-channel refit re-solved on it, then sv_final to L8).

**Gate G0:** the unrounded (exact) arm's rel_B equals w87's stored i8 rows (K2.5, K4) and w95's (K0.5) within 1e-6
relative (same tensor, sample 0, σ). Fail → nothing is read.

**Rule.** r = rel_B(L8) / rel_B(fp16) per (tensor, K); R(K) = geo mean over tensors. **Pass at K: R(K) ≤ 1.001**
(≤ +0.1% proxy, the task's bar).
- Pass at all three K → propose L8 su / sv as a per-tensor format field at every level.
- Pass at some K only → report the K range where it passes and the bpw saved there; the lead decides (a per-level
  format flag is possible, but its saving below the passing K is what counts).
- Fail at every K → not adopted.
- Reported: bpw saved = 8 (N + Kd) / (N Kd) per trunk tensor and over the trunk (checkpoint shapes), the format and
  kernel change (decode = sign | exp2 LUT, 128 entries; where radiance applies suh / svh), the reported-only arms.
- Caveat stated with the result: the proxy refits only the output channels (production's refit_scales also refits
  suh after LDLQ); rounding error per entry does not depend on that, but the su values differ.

**Runtime cost:** if adopted, a format change (exl3i field) and a dequant of the scales (load-time expansion to fp16
keeps kernels unchanged but saves only file bytes, not VRAM; in-kernel LUT saves both).

**Rule.** "Agent-heavy" = a heavy block's agentic token share ≥ 2× the collection's mean share.
- Heavy blocks agent-heavy → block normalisation already down-weights agentic text and won: a category-matched

  variant); say so.

  4070 is off limits, so it waits).
