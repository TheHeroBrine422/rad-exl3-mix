# w71 · #113 · A 2^20-state trellis searched by a beam vs our 2^16-state Viterbi (CPU proxy, format decision)

(09:35 UTC), before any deciding data.** Data before that point, none of it on the deciding set: the synthetic checks
(iid Gaussian tiles, `w71/test71.py`, `w71/hashdiag.py`, `w71/timing71.py`) and two fwd-order gate runs on 11 attn_k
(K2: S16 / F16 / T16 / V16 / B20-256; K3: S16). Results and readouts go under "Results" at the end; the rule text is
not edited after data (amendments get a date and go below the rule they change).

**Why.** An outside entry (radiance PR #364, IQR "KL-guided" quants) uses IQR's computed trellis with a 20-bit
state window on most lines, searched by an M-algorithm beam (`tcq_beam=4096`) instead of full Viterbi over 2^16
states. A computed code costs no table bytes for the extra states, and QTIP's analysis says distortion keeps falling
with the window. Our EXL3 trellis (mul1 / mul1_i8, computed) reads a 16-bit window. A wider window changes the
format (every decoder reads wider windows), so it has to be decided before the ladder.

## Code (`v3/e3/settle/w71/`; box: colo `/data/work/w71/`, nice 10, one thread a job, ≤ 24 jobs)

- `beamL.c` — the bitshift trellis with an L-bit window on 16×16 tiles, integer K: state
  s_i = ((s_{i−1} << K) | x_i) & (2^L − 1), value cb[s_i]. Full Viterbi (viterbi.c's loops with 16 → L, same
  arithmetic order and tie rules) or the M-algorithm beam (survivors are distinct states; survivors sharing their low
  L − K bits have the same children, so each such group keeps its cheapest member; the 2^K children of each kept
  parent are scored, the M cheapest survive, exact selection by value histograms, ties lowest index). Tail-biting as
  today: exllamav3's heuristic (`quantize_tiles_kernel.cuh`, viterbi.c `viterbi_tiles_tb` ntry 1): a free run on
  the tile rolled by 128 gives the wrap group c, then one run with the start in {(c << K) | x} and the end state's
  low L − K bits forced to c (the beam fixes the bits of the last symbols that land there). `-O3 -march=native`.
- `trellisL.py` — ctypes wrapper and the **L-bit codebook** (below).
- `settle71.py` — w64's `settle64.py` (exllamav3's LDLQ block order, `SETTLE_ORDER=rev`; w64.md item 0) with the
  per-tile search swapped per arm; everything else is settle.py unchanged (P2 transforms on 128 aligned rows,
  adopted damping, exllamav3's g_scale search, rel after the per-output-channel refit under the undamped calib H).
  Every V / B arm quantizes at V16's g_scale (searched once per (tensor, sample, K), shared through a scale file).
- `q71.py` (queue runner, w64's q64.py pattern), `plan71.py` (job list), `report71.py` (tables), `test71.py`
  (synthetic self-checks), `hashdiag.py` (synthetic code-vs-window check), `timing71.py`.
- Order: w64's item 0 fix is in `w64/settle64.py` (the 16-column blocks LDLQ'd last to first, each block's column
  order kept; `SETTLE_ORDER=fwd` reproduces settle.py bit for bit). I import it unchanged. Its GPU agreement check
  (w64.md item 0) had no readout when this was written; if it fails, these results inherit the caveat.

### The codebook for an L-bit state (what a decoder computes)

Exactly today's mul1 decode with a wider window mask:
`h = (s · 0x83DCD12D) mod 2^32; bs = byte0(h) + byte1(h) + byte2(h) + byte3(h)` (0..1020), value = today's value of
bs (mul1: the affine map `fp16(1024 + bs) · k_inv + k_bias`; mul1_i8: then the int8 grid). The value set and the
arithmetic are unchanged; only the window (0xffff → 2^L − 1) differs, and at L = 16 it is today's table bit for bit
(checked). The C search reads a 2^L-entry table of these values (4 MiB at L = 20) only as the encoder's cache.
Codebook as the ladder: mul1_i8 below K6, mul1 at K6.

**Decode cost (estimate from exllamav3's `exl3_dq.cuh`, not measured).** Today, per value: the window extract
(BFE / mask, with one funnel shift shared by a group of 8 values), `v_mul_lo_u32` by 0x83DCD12D, `v_dot4_u32_u8`
(byte sum + the fp16 exponent bias), half of a packed fp16 FMA (+ the int8 round for mul1_i8). At L = 20 the
multiply, byte sum and FMA are the same instructions; the mask is a 20-bit BFE / literal AND (same cost). What
changes is the bit fetch: a group of 8 consecutive values spans L + 7K bits (K2 34 vs 30, K3 41 vs 37, K4 48 vs 44),
so the aligned fast paths (`dq8_aligned_2bits` gets all 8 windows of K2 from one 32-bit funnel-shifted word,
`dq8_aligned_4bits` from b + one shift) need one more funnel shift per 8 values: **≈ +0.1–0.25 VALU per value on
~4–5 today (≈ 2–5%), same bytes, same memory traffic.** L = 18: K2 still fits one word (32 bits), so no change there; otherwise as L = 20.
Encoder: the full Viterbi's work and its 2^L cost / backpointer arrays scale ×2^(L−16); the beam's work scales with
M · 2^K (measured below).

*Correction 2026-11-07 4:40 AM CST (decode estimate only, not the rule): our shipped decoder is radiance's
`plugin/exl3r4d/exl3r4d_common.hip.h`, not exllamav3's, and it depends on 16-bit states.* Its adopted hash
(`EXL3_HASH 2` + `EXL3R4D_V1CD`) packs two 16-bit states in one dword and hashes both with 2 × `v_pk_mul_lo_u16` +
2 × `v_mad_u32_u16` (2 full-rate ops a state, using s · 0x83DCD12D = s · 0xD12D + (lo16(s · 0x83DC) << 16), exact
only for s < 2^16), and at K4 it pulls a state pair out of the stream with one `v_perm_b32` (states byte-aligned).
With an 18- or 20-bit state neither trick holds: per state one `v_bfe_u32` + `v_mul_u32_u24` × 2 + `v_lshl_add_u32`
(the 24-bit form the file already documents; or a quarter-rate `v_mul_lo_u32`). Per run of 4 values, counting the
alignbit, extraction, hash, 4 `v_sad_u8` and 2 packed FMAs: **K4 18 → 23 VALU (+28%), other K 21 → 23 (+10%)**, and
the extra mid word is needed from K5 (3K + 20 > 32) instead of K6. L = 18 costs the same as L = 20. So a wider window
is +0.5–1.25 VALU a value (+10–28% of the dequant ALU) in both the prefill GEMM's and the decode GEMV's K loops, on top
of the encoder cost; estimated from the source, not measured.

## Rule (#113)

r(arm) = rel(arm) / rel(V16), paired per (tensor, sample, K). Per K: G(arm) = geometric mean over the 54
(tensor, sample); per tensor: t(arm) = geometric mean over its two samples.
For L = 20: M*(K) = the M ∈ {256, 1024, 4096} with the lowest G(B20-M) at that K.
- **ADOPT-FOR-27B-CHECK** if at ≥ 2 of K2 / K3 / K4: G(B20-M*) ≤ **0.970** (≥ 3% less proxy error) **and** no
  tensor worse (every t(B20-M*) ≤ 1.000). Then the next step is a 27B check (a real quant of a few layers with a
  20-bit window needs an encoder and decoder build: the lead schedules it).
- **NOT ADOPTED** otherwise: the window stays 16 bits for V3.
- **L = 18** (the cheaper middle) is read by the same thresholds with its best search (V18, and B18-M), reported as
  "would pass / would not" next to L = 20.
- Reported, not deciding: K5 / K6 G and t; V20 (L = 20 with exact search: what the window is worth if the search
  were not the limit); per-family G; encode time per arm (seconds of the LDLQ pass, ratio to V16, and the GPU
  estimate); the decode estimate above; the synthetic code check (mul1's L-bit form vs an iid table and IQR's
  `mad` code at L = 16 / 18 / 20).

**Runtime cost.** If adopted: **decode and prefill** (the dequant in both paths reads wider windows: +0.1–0.25 VALU
