# #144 · w109 · swj level-pass speed (rule, written before data)

Task `local/workers/instr3/w109.md` (user go 11-11). Code under test: `pipeline/rxq/swjfit.py` + `swjtri.py`,
`forward.py`, `deq.py`, `swj.py` at rad-exl3-mix 640ecfd (unchanged since 33cab29, 11-07: the code of w92's /
w99's production passes). Candidates live in `v3/e3/settle/w109/` (copies / patches; shared code is not edited in
place). Measurement and tooling, not a quantizer decision: `[post.swj]` is not changed by anything here.

**Inputs.** Sources = w92's two K2.5 i8 levels (`/data/w92/lv/fs0`, `fs1` on gpubox; on dad1 a copy of the first
layers' shards with a truncated index), META = `swj27-qad` (725 qad docs, 927,611 tokens, cap 4096, sha fa9392e2..),
bf16 Qwen3.8-27B. Dev runs use a truncated model (the first L decoder layers: config `num_hidden_layers` L, same
tensors) and `--maxdocs N`; production numbers are scaled to 64 layers × 927,611 tokens from per-layer-token times.
More than 2 sources in one pass = the same level dirs under further names (time does not depend on the codes).

**1. Profile** (dad1 9070 XT gfx1201 under dad1's card0.lock; a gpubox card-0 run under card0.lock + ram.lock shared
if a short slot is free). Per stage: load, embed / boundary read, bf16 layer forward, the hook's reference f32 gate /
up GEMMs + SwiGLU, per source the f32 GEMMs and the grid sums (fused Triton), boundary writes (incl. fsync), sum
checkpoints, decode of the sources (`rxq.deq`), host↔device copies, idle. Timers synchronize, so shares are
reported with the unsynchronized wall beside them. Also: time per layer vs number of sources S ∈ {1, 2, 4} (+ the
existing gpubox timing.jsonl of w99 S=1, w92 S=2, swj27 S=4 passes) → model t(S) = base + S × per-source.

**2a. Output-identical speedups (the target).** Judge, per candidate, on the profiled layers and docs, same machine,
same software as the reference run of today's code:
- every `scales/<key>.safetensors` of every source: tensors `r` and `c` torch.equal to the reference's;
- every `swiglu.jsonl` record equal (floats compared exactly); `swjfit.json` equal except tool / created / kernels /
  any new field the candidate adds.
Any difference = the candidate is rejected as is (no tolerance; a "near-identical" change is a (b) proposal).
Speed = the pass's wall (first stage load → `.done` of the last source), one run each, same box, nothing else on
the card; a candidate counts as faster only at ≥ 5% (dev runs of a few minutes: run-to-run noise ~2-3%). On gpubox,
if card time allows: the full 725 docs on the first stage's layers, compared also to w92's production
`/data/w92/swj/fs{0,1}/scales` for those layers (same rule: torch.equal).

**2b. Result-changing proposals** (only if (a) leaves swj > 20% of the projected ladder card time; never adopted
here: any `[post.swj]` change is a settings-stamp change the user decides). Judge: the fit's own held-out residual
(`heldout_joint`, odd documents, fit on even), per layer and source, vs today's settings on the same source:
held-out gain G = heldout_base − heldout_joint; a proposal passes if mean over layers of (G_today − G_prop) / G_today
≤ the seed spread = mean over layers of |G(fs0) − G(fs1)| / mean G (the two seeds' levels, today's settings), on
≥ 8 layers including a full-attention layer and both sources.

**3. Projection** (w105's method): ladder card-days = w105's quant hours at today's stamp (49–53 h × 12,800 /
12,800, unchanged) + swj passes: 36 levels (≤ K4.5) / S per pass × the measured pass time for S sources scaled to
64 layers × 927,611 tokens on the R9700 (dad1 → R9700 by the ratio of the two boxes' times on the same dev run, or
gpubox's own if measured). Also the 9070 XT 16 GB: max S per pass and its time, whether swj can move to dad1.
