# #77 tile CD (cd3) on attn_qg at 27B: "does no harm" swap pairs, rule

Written 2026-11-06 ~12:45 PM CST by w50, before any 27B CD data. Code: `v3/e3/tilecd/` (the GPU implementation
`tilecd.py` + `ourq-tilecd.patch`, the driver `cd27.sh`, the verdict `cd27verdict.py`, the q2 insert
`insert-40-cd27.sh`). The pattern is SWJ27.md / ASYM27.md's: a few tensors of an existing swap-test level replaced,
the rest of the level unchanged.

## Question

The user adopted tile CD for attn_qg only (2026-11-06), on the CPU proxy (w43, `README.md` item 3). There, cd3 ÷ LDLQ
on attn_qg was 0.963 / 0.976 / 0.978 / 0.976 / 0.975 at K1.5 / 2 / 3 / 4 / 6; on every other family it was 0.99 or
higher. The CPU cost was 3.2× the encode time. Before the ladder uses it, this check asks one thing: does cd3 on the 16
attn_qg tensors leave the 27B's KLD no worse?

The gain is not expected to be measurable. attn_qg is 16 × 12,288 × 5,120 = 1.01B weights, 3.7% of the model. A
~2.5% lower proxy error on those tensors moves the model's KLD by much less than one pair's noise. So this is a
safety check, not a gain test: it would catch a broken implementation or an unexpected interaction (the
per-channel scale refit, the i8 codebook, the qtf2 kernels). It cannot show the gain.

**Added the same day, after the 4070 check and before any 27B data (the rule below is unchanged).** On the real
quantizer, cd3 on attn_qg gains less than the proxy said:
- cd3 ÷ LDLQ is 0.987–0.996 (layers 3 / 19 / 43, K2–4; `v3/e3/tilecd/README.md`), about −0.7% geo.
- That is still the largest gain of the families on the card (the others gain 0.2–0.4% at K2.5; attn_k is close), but
  about a third of the proxy's 2.2–3.7%.
- The proxy's larger gain came from layer 3 under its first-to-last LDLQ order. exllamav3 runs LDLQ last-to-first
  and does not leave that error.

This check still answers its question (no harm). Whether "attn_qg only" is still the right scope is a separate
decision for the user.

## Arms

Two seed pairs (H27 amendment 4), K2.5, no H_out, the ladder's settings as made (qtf2, scaled H, σ 0.025 / input
0.005, i8). Each pair's settings are read from its level's own stamp.json by `levelargs.py`.

| arm | level (every tensor except attn_qg) | attn_qg | control (paired) |
|---|---|---|---|
| `s1cd` | `/data/swap27/q-s1/K2.5` (seed offset 1) | requantized, `--tile-cd 3 --tile-cd-families attn_qg` | `s1` (`/data/swap27/s1.json.rows`) |
| `basecd` | `/data/v3ladder2/K2.5` (seed offset 0) | the same | `base` (`/data/swap27/base.json.rows`) |

- **Codes.** The 16 `self_attn.q_proj` tensors (layers 3, 7, …, 63) are requantized with `ourq.py --only` (the level's
  args, seeds and calib H), plus 3 CD sweeps after LDLQ. The level's other 320 trunk tensors are kept bit for bit
  (`assemble.py build`). Each q_proj is first in its Hessian group, so `--only` reproduces its full-run seed and
  Hessian state.
- **No-op gate.** The same 16 tensors are first requantized without `--tile-cd`. If they come out bit-identical to the
  level's (`assemble.py same`), the existing score is the control. If not (code or build drift since the level was
  made), the control becomes `<arm>n` = the level + these no-CD tensors, packed and scored in the same run. That way
  drift is never read as the CD effect.
- **Scoring.** As in every swap arm (`swap27.sh` / `swap27k.sh` functions, sourced unchanged):
  - packed as exl3i (mul1i8, rate 2.5) and mixed into V2 3.00, then checked by census;
  - plugin home `/data/swap27/home`;
  - `golden-search27` (search pool, 103 docs, 123,460 positions, 8k cap), bf16 KV;
  - `tools/paired.py`: per-document paired difference, bootstrap SE.

## Rule

Let r_i = KLD(arm_i) / KLD(control_i) for i = s1, base, and g = √(r_s1 · r_base).

- **PASS ("does no harm"):** g ≤ 1.000 **and** r_s1 ≤ 1.01 **and** r_base ≤ 1.01. Then cd3 on attn_qg goes into the ladder
  (`--tile-cd 3 --tile-cd-families attn_qg` at every level). `cd27verdict.py` prints the verdict.
- **FAIL:** anything else (g > 1.000, or either pair > 1.01). cd3 is then not adopted from this check. The data go to
  BACKLOG "proxy negatives to reconsider", with the q_proj proxy errors (cd / noop) and the per-pair z. A pair above
  1.01 also triggers a look for an implementation error: decode the arm's attn_qg codes and compare them with the
  quantizer's returned weights.
- Both pairs are required. Each pair alone has no quantization noise in its contrast beyond the 16 tensors, but the
  CD gain depends on the particular codes; two seeds decide whether the setting is safe, not one quant.
- Single verdict. No third pair, no reruns on another slice. Verify (clean verify slice) only once after the
  decision, as for every adopted setting, never iterated on.

**Report, not gating:**
- the paired z and relative SE of each pair;
- `q-cd/tilecd.jsonl`: quantization-domain rel after LDLQ and after each sweep, ratio, accepted tile shares, seconds;
- the q_proj proxy_err ratio cd / noop after the scale refit (`proxy.jsonl`): the GPU analogue of settle.py's rel;
- the CD time per tensor on the R9700 (from `tilecd.jsonl`) beside the 4070's (`v3/e3/tilecd/README.md`).

**Runtime cost:** none. Codes only: same format, kernels, bpw, prefill and decode. Quantizer cost: 3 sweeps per
attn_qg tensor, measured on the 4070 in `v3/e3/tilecd/README.md` (16 tensors per level).

## Result (2026-11-06 ~8:55 PM CST, from `docs/experiments/LOG.md`)

Both no-op gates passed (the private tree reproduced each level's q_proj bit for bit), so the existing scores were the
controls. s1 → s1cd **0.9994**, base → basecd **0.9997** (z −0.3); g = **0.9996**, no pair > 1.01 → **PASS ("does no
harm")**. As expected, the whole-model effect is within noise; cd3 on attn_qg is adopted on its per-tensor gain and
this check (user, 2026-11-06). In the pipeline: `[quant.tile_cd]` in `pipeline/config/v3.toml` (the switch flips once
tilecd.py is merged).
