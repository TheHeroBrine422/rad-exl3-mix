# w128 rule: #168-01 — does the ROCm guard's rocBLAS switch keep swj's results? (written 2026-11-12 ~9:05 PM CST, before data)

**Context.** #168: on the pip ROCm 7.14 hosts (ds8, box2) every swj pass memory-faults within minutes: rocBLAS runs the
GEMMs inside batched trsm (transformers' torch GDN, `torch.linalg.solve_triangular`) on hipBLASLt with pointer arrays
from `hipMallocAsync`, and a trim of HIP's default memory pool (VmHeap) makes a later GEMM read null pointers. Two
mitigations, both clean in the stress repro (`rad-local/workers/w128/trsmstress.py`):
- **K** (keep): the default pool's release threshold = UINT64_MAX. Same kernels: the results of today's default path.
- **R** (rocBLAS): `ROCBLAS_USE_HIPBLASLT_BATCHED=0`. rocBLAS's own batched trsm kernels: the GDN forward moves at the
  f32-rounding level; ~10% faster pass (box2: 1,700 vs 1,555 tok/s, fused + bf16).

**Question.** Does R (with K) keep swj's held-out gain, i.e. may the guard set it?

**Arms** (ds8 HIP 7 by card7.lock, the same card for both, one after the other): DEF = K only (today's numerics);
FIX = R + K (the guard as patched in `rxq/forward.py`). Both `rxq.swjfit --fused --no-cache --numerics bf16`,
sources the ladder levels `q27v3-144dd6e1-k2.5-i8` and `-k4-i8` (`:level`), META `swj27-qad`, `--maxdocs 240`
(the first 240 qad-pool docs, as the production META; held-out = odd docs), default grid / cap.

**Metric** (w109's `bstat.py` quantities): per source and layer G = heldout_base − heldout_joint; loss = mean over the
64 layers of (G_DEF − G_FIX) / G_DEF (positive = FIX worse).

**Decision.** ADOPT R in the guard iff loss ≤ +0.001 (0.1%, #144's "held-out gain within 0.1%") for **both**
sources. Otherwise the guard is K only (no numerics change). Reported, not judged: share of channels whose c moved
(gate / all), max |dc| — #144's references: bf16 numerics moved gate c on 1.4–2.8%, two gfx1201 boxes 2.2%.

**Not covered.** A comparison with gpubox's bf16 path on the same level (gpubox off limits for w128); both arms differ
from gpubox's older ROCm stack at the same order as #144's box-to-box difference.
