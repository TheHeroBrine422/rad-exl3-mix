# 27B diagonal H_out: swap-test pass rule (written 2026-11-03 ~10:05 AM CST, before any 27B data)

Arms (night27.sh, card 0, ladder settings, i8): **K3** = the ladder's level (`/data/v3ladder2/K3`, seed 0, no H_out),
**K3-dy** = + diagonal H_out (Σdy², gen-masked, 512 long qad windows, output damping 0.01), **K3-s1** = K3 at rotation
seed offset 1 (the 27B quant-noise floor). Each scored as a whole uniform-K3 trunk (d0.sh path, bf16 KV) on a
**search-pool** slice of ~100k scored positions (8k cap); paired per document, bootstrap over documents
(`mix/paired.py`). Verify only once, after the decision.

- **Noise floor:** n = |log(KLD(K3-s1) / KLD(K3))| (one seed pair; the 0.8B says ~1% at K3).
- **Real** (question 1): KLD(K3-dy) / KLD(K3) has its bootstrap 95% upper bound < 1 **and** |log ratio| ≥ 2 n.
- **Worth it** (question 2): H_out is free at runtime (quantizer-side) and its collection is already paid, so any real
  gain is adopted for the trunk requant; ≥ −3% (0.8B shrunk by half) is the expectation, smaller real gains are still
  adopted. If K3-dy ≤ 0.97 also run K2.5. Snapshot for the requant: the 27B's own dose curve decides (collection to
  2,048; compare snapshots by split-half agreement and, if they differ, a K3 quant at 1,024 vs 2,048).
- **Fail:** ratio ≥ 1.00, or not distinguishable from the seed floor: then the 0.8B result does not transfer (log it
  in BACKLOG "proxy negatives to reconsider" with the depth / matrix-size mechanism) and the trunk stays H_in only.
- Runtime cost: none (quantizer-side only).

## Amendment (2026-11-04 ~4:30 PM CST, before any swap-test data)
The K3 ladder level was lost in the gpubox crash; the recovered base is **K2.5** (`/data/v3ladder2/K2.5`, ladder
settings, seed 0, no H_out). And the 27B Σdy² diagonal is heavy-tailed (#33-27): a block-normalized estimator (every
128-sequence block scaled to the same per-tensor total) beat the plain mean on the 3-layer proxy (hconv, 0.926 vs
0.942). So the test runs at K2.5 with two H_out arms, all from the full 2,048-sequence collection:
- **K2.5** (base, existing) · **K2.5-dy** (+ plain Σdy² mean, output damping 0.01) · **K2.5-bn** (+ block-normalized
  Σdy², same damping) · **K2.5-s1** (no H_out, rotation seed offset 1: the noise floor).
- Each trunk imported as exl3i (mul1i8, rate 2.5) and swapped into V2 3.00 (V2's head and embedding), served by radiance
  1.16.0 with our plugins (the same build for every arm), scored on a fresh **search-pool** slice (~100k scored
  positions, documents capped at 8k), bf16 KV; paired per document (`mix/paired.py`).
- **Real** for an arm: its paired 95% upper bound vs K2.5 < 1 **and** |log ratio| ≥ 2 n, n = |log(K2.5-s1 / K2.5)|.
- **Which estimator:** bn is used for the requant if it is real and not worse than dy by more than the bn-vs-dy
  interval allows (upper bound of bn/dy < 1.01); otherwise dy if it is real. If neither is real: fail as above.
- Worth it: as above (no runtime cost, collection paid): any real gain is adopted.
- Order on the card: K2.5-bn, K2.5-dy, K2.5-s1 (the bn arm answers the main question first).
